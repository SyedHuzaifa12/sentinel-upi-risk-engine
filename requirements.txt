# Pinned to 0.48.0, NOT the latest (0.51.0): shap>=0.49 declares numpy>=2 in
# its own install_requires, which is a genuine, pip-enforced conflict against
# numpy==1.23.4 pinned above for pandas 1.5.1 compatibility (pandas 1.5.1's
# compiled extensions are ABI-incompatible with numpy 2.x and crash on
# import) -- this broke a from-scratch `pip install -r requirements.txt` in
# CI with ResolutionImpossible, even though it appeared to work locally
# (pip doesn't re-verify/downgrade an already-installed numpy when you
# install shap as a separate, later command -- a fresh single-pass resolve,
# which is exactly what CI does, correctly refuses it instead).
# shap==0.48.0's own install_requires just says `numpy` (no version floor;
# the numpy<2.0 constraint only applies to its unused "test" extra), and its
# transitive numba>=0.54 dependency resolves to numba 0.67.0, which requires
# numpy<2.6,>=1.22 -- comfortably satisfied by numpy==1.23.4. Verified with a
# from-scratch install into a clean venv (no ResolutionImpossible) and by
# re-running ml/tests/test_policy.py and service/tests against it.
# Do not let pip "fix" this by upgrading numpy. Separately (unrelated to
# shap): `import lightgbm` must happen before `import pandas` in any process
# that also touches LightGBM's C API, or it crashes with an access violation
# -- see the comment in reason_codes.py and service/scoring.py.
